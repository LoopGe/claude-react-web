# Native P1.3 — Subagents Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native-provider session can call an `Agent` tool that runs a nested turn loop with its own history, emits sidechain frames (`parent_tool_use_id = <agent tool_use id>`), and renders through the existing SubagentCard/SubagentOverlay/SubagentSwarm — with sidechain frames persisted so resume/fork/history pages keep the subagent transcript.

**Architecture:** `Agent` is a per-session `ToolDef` (not a global static): its closure captures the session's stream seam, model, cwd, permission handler and emitter. `runTurn` is re-entered with a fresh `history`, a nested `deps.system`/`deps.tools` (the parent's tools minus `Agent`, so depth is capped at 1), and a nested emitter that stamps `parent_tool_use_id` on every frame and suppresses the nested `result` frame. Sidechain frames are persisted into the same append-only session log with their real parent id; replay (`historyFromEvents`) and crash repair exclude sidechain from the MAIN model history, while the reader/cache includes sidechain lines so resume and history pages keep them. Sync only: the tool returns the subagent's last non-empty assistant text as its `tool_result`.

**Tech Stack:** TypeScript ESM (`.js` suffixes), Node 20, no new dependencies; vitest.

**Spec:** `docs/superpowers/specs/2026-11-09-native-session-persistence-design.md` (add a P1.3 section in Task 5).

## Global Constraints

- No behavior change for `server/providers/claude/**` or for the shared `isRenderableSdkMessage` predicate (the seq-store ingest gate). The native session-log cache may widen ITS inclusion to keep sidechain lines; the seq store must still skip them.
- The nested turn must not emit a second top-level `result` frame, must not register prompt sections, and must not call `Agent` recursively (depth cap 1).
- Subagent tools inherit the parent's tools minus `Agent` (including MCP/first-party defs) and the parent's permission handler/mode — a subagent never widens permission scope.
- `run_in_background`, task frames (`task_started`/`task_notification`/`task_progress`), task control (`backgroundTasks`/`stopTask`), `Task`/`Explore` aliases, progress summaries, and `listSubagents` are all OUT OF SCOPE (P1.3b+).
- No new dependencies; diagnostics through `createLogger`; tests focused first, full gate before the final commit.

## Review Focus

1. **No main-history contamination** — after resume, `historyFromEvents` never returns sidechain events, and `repairInterruptedTurn`/`repairRenderableLines` never synthesize a top-level tool_result for a sidechain `tool_use`.
2. **Exactly one terminal result per turn** — the nested invocation emits zero `result` frames; the parent's `result` frame count stays 1.
3. **Frame parentage end-to-end** — every sidechain assistant/user frame carries the Agent `tool_use.id` (live and on disk), and top-level frames keep `parent_tool_use_id: null`.
4. **Usage accounting** — `usageByModel` includes subagent assistant usage; `lastUsage`/context-window accounting reads the last TOP-LEVEL assistant frame only.
5. **Abort propagation** — interrupting the parent turn aborts the nested loop (same signal), and the parent's remaining tool calls still get synthetic aborted results.
6. **Result-text selection** — the tool result is the last non-empty assistant text of the nested run, with a non-empty placeholder when the subagent produced no text.

Each line gets a test in the owning task.

### Task 2: The nested subagent runner and Agent tool factory

**Files:**
- Create: `server/providers/native/subagent.ts`
- Create: `server/providers/native/subagent.test.ts`
- Modify: `server/providers/native/native-session.ts` (`streamFor`/`defaultStream` gain `opts?: { suppressRetryFrames?: boolean }` so nested retries never emit top-level `api_retry` frames)

**Interfaces:**
- Consumes: `runTurn` (Task 1's `emitResult`), `FrameContext.parentToolUseId`, `ToolContext.toolUseId`.
- Produces:
  ```ts
  export interface AgentToolDeps {
    cwd: string
    model: () => string                      // LIVE getter (a mid-session setModel must not stale the fallback)
    system: string
    frameCtx: FrameContext                 // the session's ctx (Task 1 adds parentToolUseId)
    tools: () => ToolDef[]                 // LIVE getter: builtins + current MCP defs
    streamFor(req: { model: string; system: string; tools: unknown[]; messages: unknown[]; signal: AbortSignal }, opts?: { suppressRetryFrames?: boolean }): AsyncIterable<CanonicalEvent>
    requestPermission: LoopDeps['requestPermission']
    emit(frame: AgentMessage): void        // already persists + pushes (parent comes from frameCtx)
    agentStore?: AgentDefinitionStore
  }
  export function createAgentTool(deps: AgentToolDeps): ToolDef
  ```
  `Agent` tool: `name: 'Agent'`, `promptOrder: 80`, `guidance` = a one-line delegation hint, schema `{type:'object', properties:{description:{type:'string'}, prompt:{type:'string'}, subagent_type:{type:'string'}, model:{type:'string'}}, required:['description','prompt']}`.
  Behavior of `run(input, ctx)`:
  - Resolve the agent type: `'general-purpose'` (or absent) uses a default subagent instruction; a name present in `agentStore` (enabled) uses its `prompt` as the nested system prompt suffix and its `model` as default. Unknown type → `{text: 'unknown subagent_type: …', isError: true}`.
  - Nested system = the SUBAGENT system (the parent prompt rendered WITHOUT the `tool:Agent` guidance section, so a subagent is never told it can delegate) + `'\n\n' + agentPrompt`. Nested tools = `deps.tools().filter(t => t.name !== 'Agent')` (evaluated at call time, so MCP/first-party defs are included and current). Nested model = `input.model ?? def.model ?? deps.model()`.
  - Nested history = `[]`; nested `runTurn` with `emitResult: false`, `signal: ctx.signal`, and `frameCtx = { ...deps.frameCtx, parentToolUseId: ctx.toolUseId }` (throw if `ctx.toolUseId` is undefined). The nested emit is the plain `deps.emit` — parentage comes ONLY from the ctx, never from a second stamping wrapper.
  - Abort: `if (ctx.signal.aborted) return { text: 'aborted', isError: true }` before starting and again after the nested `runTurn` returns (a scripted stream may ignore the signal).
  - Result text = the last non-empty assistant text of the nested run (collected from emitted assistant frames), falling back to `'(no output)'` when the subagent produced no text. Tool exceptions → `{text: message, isError: true}`.
  - `run_in_background` is not in the schema (out of scope).

## Execution decisions

- **Sync only.** `run_in_background` is excluded from the tool schema; task frames and task control are deferred (P1.3b). The subagent card settles through the parent's `tool_result`.
- **One log, two views.** Sidechain events persist in the same session log (so resume/pages keep them), but `historyFromEvents` and crash repair treat them as out-of-main-history. The seq store keeps excluding them (shared predicate untouched); only the native reader's cache widens to include them.
- **One parentage mechanism.** Every sidechain frame's `parent_tool_use_id` comes from `FrameContext.parentToolUseId` threaded into the nested `runTurn`; the nested emit is the session's plain emit, with no second stamping wrapper. One writer, one source of truth.
- **Live getters for model and tools.** `AgentToolDeps.model` and `.tools` are functions read at call time, so a mid-session `setModel` or MCP/first-party change is honoured by the next `Agent` call instead of being frozen at construction.
- **The nested system prompt omits the `tool:Agent` section.** The provider renders two prompts from the same registry (parent, and a subagent variant without that section), so a subagent is never told it can delegate — reinforcing the depth cap rather than relying on it alone.
- **Depth cap 1** by filtering `Agent` out of the nested tool list (not by a runtime counter).
- **Custom agents come from `AgentDefinitionStore`** (`supportedAgents` returns the built-in `general-purpose`; the route unions store definitions, matching the claude path). `input.model` is passed through verbatim (no alias resolution).
- **Nested `api_retry` frames are suppressed** via `streamFor(req, { suppressRetryFrames: true })` (retry behavior is unchanged; only the top-level session emits retry frames).
- **Entries vs pages are deliberately different.** `readNativeHistoryEntries` (search + seq backfill) filters sidechain out; `readNativeHistoryPage` (resume + history UI) keeps it. This is what keeps the seq store and search top-level without touching `composeTranscriptEntries`. Entries keep their full-stream index after the filter, so a search hit's `messageIndex` still addresses the right page row.
- **The resume seed reads `historyCap + subagentHistoryCap`.** With sidechain lines in the native page, a subagent-heavy session would otherwise spend the whole `historyCap` on sidechain and seed almost no main-thread messages; with the defaults (500 + 300) the page is 800, under `sliceWindow`'s 1000 clamp. Harmless for claude, whose pages carry no sidechain.
- **Log version stays v1** (widening `parent_tool_use_id` from literal null to `string | null`): old logs parse fine, but a NEW log containing sidechain events is rejected by an older server (`corrupt`) — downgrade-unsafe, documented.
- **Deferred:** background subagents and `run_in_background`, task frames (`task_started`/`task_notification`/`task_progress`), task control (`backgroundTasks`/`stopTask`), `Task`/`Explore` aliases, progress summaries, `listSubagents`; stored agent-definition fields beyond `prompt`/`model` (`tools`, `disallowedTools`, `maxTurns`, `background`, …); model-alias resolution (`input.model` is passed verbatim and may 400 on a short alias the CLI resolves); a fork cut inside a sidechain leaves an unanswered sidechain `tool_use` (renders as a stuck subagent card, accepted).
