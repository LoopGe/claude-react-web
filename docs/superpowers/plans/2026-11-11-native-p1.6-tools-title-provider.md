# Native P1.6 — Extra Tools, Title and Provider Selection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Native sessions gain the remaining everyday tools (Glob, LS, WebFetch, WebSearch, TodoWrite, NotebookEdit, AskUserQuestion), title generation, an honest `accountInfo`, a provider selector in the new-session dialog (plus restart/new-like-this provider preservation), and an explicit create-time rejection of `sandbox.enabled` — sandboxing itself is a separate security project, not part of this batch.

**Architecture:** Stateless tools (Glob, LS, NotebookEdit, AskUserQuestion) are static `ToolDef`s in `server/providers/native/tools/`; the two that need session services are factories constructed in `NativeSession` (`createWebFetchTool({model, profile, credentials})`, `createTodoWriteTool(state)`), appended in `rebuildTools` with manually registered prompt sections in BOTH the parent and subagent prompts. Glob reuses `grep.ts`'s pure-Node recursive walker (NO ripgrep dependency). Web access uses Node 20 `fetch` with `redirect: 'manual'`, per-hop re-validation, non-public-IP blocking (SSRF), size/time caps and `AbortSignal.any([ctx.signal, timeout])`. AskUserQuestion rides the existing `PermissionBroker` `kind: 'question'` path — the broker's denial carries the answers JSON, so the loop must treat it as a NORMAL tool result, not an error. Title generation reuses `callAnthropicMessages` (with `temperature` and a `caller` label). `accountInfo` returns `undefined` (nothing fabricated).

**Tech Stack:** TypeScript ESM (`.js` suffixes), Node 20 `fetch`, vitest, no new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-09-native-session-persistence-design.md` (add a P1.6 section in Task 7).

## Global Constraints

- No behavior change for `server/providers/claude/**` EXCEPT the intentional shared additions of `LS` to `READONLY_TOOL_NAMES` and `SAFE_AUTO_TOOLS` (a directory listing is read-only for both providers).
- Every new tool uses `resolveAgainstCwd` for filesystem paths and `capToolText` for output bounds (the only exported cap helper; `CappedOutput` is module-private).
- Web policy: HTTP(S) only, URL ≤2048 chars, no embedded credentials, `redirect: 'manual'` with per-hop re-validation, non-public IPs blocked (v4+v6 incl. 169.254.169.254 and ::1) before connect AND on every redirect, response ≤5 MB, decoded ≤100k chars, `AbortSignal.any([ctx.signal, AbortSignal.timeout(30_000)])`.
- Glob uses the pure-Node walker extracted from `grep.ts` (NO `rg` spawn). `**` and `?` glob semantics must be supported (the existing `globToRegExp` only handles `*`).
- `AskUserQuestion`'s schema matches the broker's parser exactly: `questions[]` (1–4) of `{question: string, header?: string, options: Array<{label: string, description?: string, preview?: string}> (2–4), multiSelect?: boolean}`. The broker's ANSWER paths (answer / clarify / malformed input) mark the deny result with the host-internal `QUESTION_RESULT` symbol; the loop emits it with `is_error: false` only when that marker is present. Abort, session-close (`denyAll`), missing-handler and ordinary permission denials carry no marker and stay `is_error: true`. In `bypassPermissions` the tool returns an explicit "dialog unavailable" error.
- `accountInfo()` returns `undefined`; `supportsAccountInfo: true` (the route yields `{account: null}` rather than 501). No `apiProvider`/email/org is invented.
- `generateTitle(description)` uses `callAnthropicMessages` with `temperature` and `caller: 'session-title'`, targeting `this.opts.credentials()` (the function) with `this.opts.profile?.recapModel || this.model`; `supportsSessionTitle: true`.
- `createSession` rejects `opts.sandbox?.enabled === true` with `HttpError(501, 'provider native does not support sandbox')`, and `SessionManager.create` rejects it BEFORE worktree provisioning (no orphan worktree). `SettingsPanel` hides the sandbox section for native sessions (instead of offering a control that 502s). `applyFlagSettings({sandbox})` keeps throwing. Sandboxing itself is a SEPARATE security project.
- Provider selection: `NewSessionDialog` gains a provider dropdown (`claude` / `native`); restart and `new-like-this` carry `source.provider`. `enabledPlugins` is hidden for native (unsupported); other create fields stay.
- No new dependencies; diagnostics through `createLogger`; focused tests first, full gate before the final commit.

## Review Focus

1. **Path containment and bounds** — every tool rejects escapes outside cwd; Glob caps at 100 files, LS at 100 entries, NotebookEdit never returns whole-file bodies (`original_file`/`updated_file` are dropped).
2. **Web policy + SSRF** — scheme/credential checks, non-public-IP blocking before connect and on every redirect, size/time caps, `redirect: 'manual'`, `AbortSignal.any` for interrupts; WebSearch filters domains locally and caps at 10 results, encodes the query, sends a User-Agent, and tolerates a non-2xx response as an error.
3. **AskUserQuestion lifecycle** — the broker's question path produces `{note, answers}` with `is_error: false`; `QuestionCard`/`QuestionDialog` render it; bypass mode fails loudly; the schema produces a pending `kind: 'question'`.
4. **Title/accountInfo honesty** — title resolves to a string via the aux caller with recapModel-or-current-model, `temperature` and a `caller` label; accountInfo is undefined, never invented.
5. **Provider preservation** — the new-session dropdown selects the provider, and restart/new-like-this keep the source provider; `enabledPlugins` is hidden for native.
6. **Sandbox honesty** — create rejects `sandbox.enabled` BEFORE worktree provisioning; the SettingsPanel sandbox section is hidden for native; `applyFlagSettings({sandbox})` still throws.

Each line gets a test in the owning task.

## Execution decisions

- **Sandbox is a separate security project.** DSH-grade confinement (Linux bubblewrap/Landlock, macOS Seatbelt, Windows ACL restricted-token runner with DACL mutations and only PARTIAL enforcement) is out of scope for P1.6. This batch only makes the current state honest: `createSession` rejects `sandbox.enabled` for native BEFORE worktree provisioning (no silent unenforced sandbox, no orphan worktree), the SettingsPanel sandbox section is hidden for native, and `applyFlagSettings({sandbox})` keeps throwing. A future project should define one platform/backend with explicit fail-closed semantics before exposing the setting to native sessions.
- **`accountInfo` returns `undefined`** (native has no email/org/subscription/token-source data in `ProviderProfile`). `supportsAccountInfo: true` so the route yields `{account: null}` instead of a pointless 501; no `apiProvider` is invented.
- **WebFetch and TodoWrite are per-session factories**, not static `ToolDef`s (they need the model/credentials and per-session state respectively). Their prompt sections are registered manually in both the parent and subagent prompts.
- **WebSearch uses DuckDuckGo HTML** (no API key required) with `encodeURIComponent`, a browser-like User-Agent, local domain filtering and a 10-result cap. A non-2xx response is an error, not a silent empty result.
- **TodoWrite's warning lives inside the JSON.** Multiple `in_progress` todos are accepted (a planning smell, not a malformed call) and the result is `{oldTodos, newTodos, warning?}` — the review moved the warning from appended prose into the payload so the whole result always parses.
- **NotebookEdit reports the cell's raw output type.** `cell_type` in the result is the cell's own type (`code` / `markdown` / `raw`); only INSERT input is restricted to `code` / `markdown`. The result stays the changed cell only — no `original_file` / `updated_file` bodies.
- **`AskUserQuestion`'s answer is an explicit broker marker, not the tool name.** `answerQuestion` / `clarifyQuestion` / malformed input set the host-internal `QUESTION_RESULT` symbol; the loop emits `is_error: false` only when that marker survives `requestPermission`. Aborts, `denyAll` ("session closed"), missing handlers and ordinary permission denials carry no marker and stay `is_error: true`. In `bypassPermissions` the tool fails loudly (no dialog available).
- **Title prompt behavior:** `generateTitle` sends the fixed `TITLE_PROMPT` ("Generate a concise session title in the same language as the request. Return only the title, without quotes, a prefix, or trailing punctuation.") as `system`, resolves the model at call time as `profile.recapModel || this.model`, and uses `maxTokens: 64` / `temperature: 0.3` / `caller: 'session-title'` against the session profile's credentials. The manager trims the string and refuses to overwrite an existing title (checked before AND after the await).
- **Provider selection is a dropdown in `NewSessionDialog`** (`claude` / `native`); restart and `new-like-this` now carry `source.provider` (they previously dropped it and silently reverted to claude). `enabledPlugins` is hidden for native (unsupported); other create fields stay. Until a `defaultProvider` config exists, the server default stays the explicit `'claude'`.
- **Deferred:** sandboxing itself (separate project), `Options.sandbox` beyond the create rejection, `renameSession`/provider transcript retitling, a `GET /api/providers` endpoint, a provider chip in ChatPanel, `defaultProvider` config.
