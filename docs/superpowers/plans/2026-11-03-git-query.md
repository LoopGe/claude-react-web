# GitQuery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用一个内部 `useGitQuery<T>` 合并九个 Git 只读查询 hooks 的生命周期，并统一 disabled 状态、请求/snapshot 竞态和 status rejected-frame 行为。

**Architecture:** 原 `useGitStatus.ts` 保留九个公开领域 adapters；新 core 用 operation token + AbortController 管理 HTTP，用纯 functional update 原子执行 external accept/equal/data 提交。snapshot 继续直接应用，绝不退化为 refetch。

**Tech Stack:** React 19、TypeScript、Vitest、@testing-library/react、现有 `api` 与 Git WS snapshot listener。

**Spec:** `docs/superpowers/specs/2026-11-03-git-query-design.md`

## Global Constraints

- 九个公开 hook 的名称、参数和 `{data,loading,error,refresh}` 返回形状不变，不暴露 `applyExternal`。
- disabled/参数缺失统一 `data=null、error=null、loading=false`，并使 token 失效、abort 当前 HTTP。
- key/refresh 保留旧 data、`loading=true、error=null`；失败 `data=null、error=message、loading=false`。
- 接受的 snapshot 直接替换、`loading=false、error=null`，获得新 token并 abort 较早 HTTP；错 status frame 完全 no-op。
- status HTTP+WS 用 sameStatus；branches/stashes 仅 WS JSON compare；其余六个不新增 deep equality。
- 保持 lazy/eager、commit cache、query builders、组件 import 路径及 `useGitWrite` 不变。
- 不引入全局缓存、staleTime、请求去重、全局 snapshot store 或额外 WS。
- 只 stage 每个任务列出的文件，不混入其他工作树改动。

## Review Focus

- **请求中 disable/missing input：** loading 必须清零且迟到响应 no-op；由 Task 1/2 的统一状态测试覆盖。
- **snapshot 与 HTTP 交错：** 接受的 snapshot 后旧 HTTP 不得覆盖；由 Task 1 core 与 Task 3 adapter 测试覆盖。
- **错 status frame：** data/loading/error/token 全不变，当前 HTTP 可继续；由 Task 1/3 的 reject 测试覆盖。
- **callback/query key 完整性：** 相同 key 不得请求风暴，staged/mergeBase/limit/path/hash/from/to 必须触发正确请求；由 Task 1/2 测试覆盖。
- **公开兼容与请求次数：** commit cache、diff 重开、branches/stashes open、log eager 行为不变；由 Task 2/3 领域测试覆盖。

### Task 1: 建立 `useGitQuery<T>` core

**Files:**
- Create: `src/hooks/useGitQuery.ts`
- Create: `src/hooks/useGitQuery.test.ts`

**Interfaces:**
- Produces:

```ts
function useGitQuery<T>(options: {
  enabled: boolean
  queryKey: string
  load: (signal: AbortSignal) => Promise<T>
  equalOnLoad?: (previous: T | null, next: T) => boolean
}): {
  data: T | null
  loading: boolean
  error: string | null
  refresh: () => void
  applyExternal: (
    next: T,
    update?: {
      accept?: (previous: T | null) => boolean
      equal?: (previous: T | null, next: T) => boolean
    },
  ) => void
}
```

- [ ] **Step 1: 写 core 状态与 deferred-race 测试**

覆盖：

1. disabled/missing input 返回 `{data:null,error:null,loading:false}`，abort 当前请求，迟到响应 no-op。
2. 首次成功、失败状态及 error message。
3. key A→B 保留旧 data 且 B loading；A 后落地不得覆盖 B。
4. 连续 refresh 只有当前 token 可提交，refresh 保留旧 data。
5. applyExternal 接受时清 loading/error、采用 next 并 abort 较早 HTTP。
6. equal 返回 true 时保留旧 data 引用，但仍获得新 token并淘汰旧 HTTP。
7. accept 拒绝时 data/loading/error/token 全不变，当前 HTTP 不 abort且随后可正常完成。
8. applyExternal 与 HTTP 交错时旧响应不得覆盖 snapshot。
9. equalOnLoad 只影响 HTTP，不改变其他成功路径引用。
10. 相同 queryKey/load identity 不重复请求；key 或 refresh 改变才增加请求。
11. unmount abort，迟到响应无 act/unhandled 警告。

- [ ] **Step 2: 运行测试并确认模块缺失 RED**

Run:

```bash
npm test -- src/hooks/useGitQuery.test.ts
```

Expected: FAIL，原因是 `./useGitQuery` 尚不存在。

- [ ] **Step 3: 实现 token + AbortController 状态机**

内部状态固定包含 `data/loading/error/token/tokenKind('http'|'external')`：

- 新 HTTP 创建 token/controller，effect cleanup abort；响应同时检查 signal 与 token。
- disabled/missing input 创建 external token、清状态并 abort。
- applyExternal 在纯 functional update 中执行 accept/equal/data/token；拒绝返回原 state。
- external token 的后续 effect abort 当前 HTTP，禁止在 updater 中 abort。
- refresh 仅增加 tick；相同 key 的 load 由后续 adapters 用 useCallback 稳定，core 不引入缓存或 WS。

### Task 3: 迁移 status/branches/stashes snapshot adapters

**Files:**
- Modify: `src/hooks/useGitStatus.ts`
- Modify: `src/hooks/useGitStatus.test.ts`

**Interfaces:**
- Consumes: Task 1 的 `applyExternal` 和现有 `useGitSnapshotListener`。
- Produces: 原 `useGitStatus/useGitBranches/useGitStashes` 接口与 snapshot sink。

- [ ] **Step 1: 写 snapshot 行为变化与兼容测试**

覆盖：

- 请求中 disable 后 loading=false 的三个统一用例。
- status 接受 authoritative repoRoot 与 pre-authoritative cwd/repoRoot frame，HTTP+WS sameStatus 引用保持。
- status 错 frame 时 data/loading/error 全不变，当前 HTTP 可继续成功。
- 三个 adapters 接受 snapshot 后旧 HTTP 不得覆盖，且零额外 GET。
- branches/stashes HTTP 成功不新增 deep compare，WS 相同内容保留引用；无 repo guard。
- 公开返回不含 `applyExternal`，open/close 请求次数不变。

- [ ] **Step 2: 运行测试并确认旧行为差异**

- [ ] **Step 3: 迁移三个 snapshot adapters**

- status：HTTP 传 `equalOnLoad: sameStatus`；listener 中以 frame envelope 构造 accept，WS 传 sameStatus。
- branches/stashes：listener 只传现有 JSON equality，不传 accept/equalOnLoad。
- 三者继续使用原 `useGitSnapshotListener`，由 core 的 external token 处理旧 HTTP；不得改成 invalidate/refetch。
- 公开返回只含四字段。
