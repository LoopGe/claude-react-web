# Native P1.1 — Context Efficiency Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make native sessions cheap across turns (Anthropic prompt caching) and safe in long conversations (in-place auto-compaction, same session id).

**Architecture:** Prompt caching is added only in the Anthropic adapter's request builder (system + last tool + last message block). Auto-compaction is an append-only `session/compact` log event: the provider resets its model history to the compacted summary, and the manager resets the same-id transcript plumbing (ring, seq sidecar, prompt/steer/turn-anchor/result-frame sidecars), broadcasts `session-cleared`, and replays the existing compact divider + summary frames. The session id never changes.

**Tech Stack:** TypeScript ESM (`.js` import suffixes), Node 20, vitest, existing `@modelcontextprotocol/sdk`-free code (no new dependencies).

**Spec:** `docs/superpowers/specs/2026-11-09-native-session-persistence-design.md`

## Global Constraints

- No behavior changes under `server/providers/claude/**`, `server/history-reader.ts`, or `server/jsonl-cache.ts`.
- No new dependencies; Node 20 only. Imports use `.js`; diagnostics use `createLogger`.
- The native log stays append-only: compaction is a `session/compact` event, never a rewrite/truncate of committed events.
- Auto-compaction keeps the same session id. It must never run while a turn or queued input is active.
- Prompt caching must not mutate the caller's `messages`/`tools` objects (the loop reuses its history across turns).
- Tests: focused file first; full gate `npm run typecheck && npm run test` before the final commit.

## Review Focus

1. **Cache breakpoints do not mutate the loop's history/tools** — the adapter clones the last message/block and the tool array.
2. **Compaction never drops an in-flight/queued turn** — the provider refuses while a turn or queue is active; the manager re-checks idle after the summary await.
3. **Same-id reset is complete** — ring, seq sidecar, `promptUuids`, steered, turn-anchor and result-frame state are reset; a new subscriber replay cannot resurrect pre-compact messages.
4. **Resume/fork after compaction starts at the compact floor** — `historyFromEvents` and the reader/page/search exclude everything before the last `session/compact`.
5. **No compaction loop** — post-compact context usage is reset/cooldown so the next trigger requires a real new turn.
6. **No fake summary on a cache-only / empty history** — `summarizeForCompact` returning `''` skips cleanly.

Each line gets a test in the owning task.

## Execution decisions

- **Transcript seq generation across the same-id store swap.** Review found that
  the reset path re-created the transcript store at generation 0, while clients
  arm a `generation + 1` stale floor when they see `session-cleared`; the
  follow-up tail fetch and live frames would then be rejected forever. Fix:
  `TranscriptStore.continueGeneration(prevGeneration)` runs after
  `removeTranscriptState`, so the store continues at `prevGeneration + 1`.
  `sm.transcriptHead(id)` is asserted as `{ generation: 1, headSeq: 2 }`
  immediately after a compact.
- **The new generation is published only inside the synchronous reset block.**
  Final review found that bumping the generation before the four awaited
  sidecar removals let a panel opening in that window adopt `N+1`; the later
  `session-cleared` then armed `N+2` and wedged the tab. The awaited removals
  now run BEFORE the bump, and the bump → ring wipe → `session-cleared` →
  compact frames are one await-free block. The fresh holder is created and
  marked `reconciled` before the removals so a racing page read sees the empty
  new space at the OLD generation (no disk backfill, which would collide with
  the boundary uuid).
- **Repair scope matches the replay floor.** `repairInterruptedTurn` now starts
  after the last `session/compact`; repairing a pre-compact open `tool_use`
  would inject an orphan `tool_result` into the compacted history (rejected by
  the API). The reader's twin already floored.
- **Boundary lookup ignores non-event lines.** `findLastCompact` skips lines
  without a numeric `seq`, so a project directory literally named
  `session/compact` in the header's `cwd` no longer makes every page/search
  read throw.
- **Config is documented and tested.** `CONFIG.md` gains `nativeAutoCompact`
  and `nativeAutoCompactRatio`; `config.test.ts` pins the defaults, the
  `(0, 1]` clamp, and the revert-to-default for a non-positive ratio.
- **Deferred minors** (deliberately out of scope for P1.1):
  - Multi-compact continuity is untested. An idle re-check without a new turn
    early-returns because `lastContextUsage` is cleared (pinned by the
    auto-compact test). A *new* turn repopulates usage, however, and does
    trigger a second compact: because `autoCompactWindow: 1` persists in
    `SessionMeta` and is re-applied on resume, the restart/resume e2e raises the
    resumed session's window so the post-compact turn is not absorbed by
    another compact. That e2e therefore does not exercise multi-compact.
  - The send-vs-reset window: a user turn landing between the idle re-check and
    the reset can be wiped from the ring AND lose its `promptUuids` pairing and
    `pendingSnapshotAnchors` entry (and the sidecar removal can race the
    echo-time save). The ring half is self-healing (the turn is persisted, so
    the next page read returns it); the prompt-uuid pairing is not. Closing it
    needs a real send queue / op lock.
  - ContextBar keeps the pre-compact percentage until the next turn produces
    fresh usage. `compactInPlace` resets the provider-side `lastUsage`, not the
    caches held by already-rendered clients.
  - The boundary and the durable summary share the compact event's uuid, while
    the live summary seed uses a fresh uuid. Re-rendering from disk therefore
    shows the summary card without the divider, and a page read racing the
    reset can collapse the boundary into the summary's seq (divider missing for
    that tab). Cosmetic; the client keys the summary card on
    `isCompactSummary`, not the uuid.
  - The e2e asserts ring/page/search content but not the boundary metadata
    (`trigger: 'auto'`, `pre_tokens`) nor the push-only nature of
    `pushCompactFrames` (that it never calls `sendControlMessage`).
