# Native P1.4 — Skills, Commands and Presets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native-provider session discovers local `SKILL.md` skills, lists them in the system prompt and the slash-command catalog, lets the model invoke them through a `Skill` tool, expands a user's `/skill args` turn into the skill body, and honors the SDK's skill policy — with `reloadSkills`/`applyFlagSettings(skillOverrides)` keeping the catalog and prompt current.

**Architecture:** A per-session `NativeSkillCatalog` wraps `server/skills.ts` `listSkills(cwd)`. An awaited `reload()` discovers skills and caches their bodies (≤1 MiB each); every read afterwards is synchronous. Selection follows the SDK contract exactly: spawn `Options.skills` (`undefined` = the CLI's **name-only** default, `'all'` = full listing, `string[]` = allowlist, `[]` = none) plus `Settings.skillOverrides` (`on` / `name-only` / `user-invocable-only` / `off`). The catalog renders an `available_skills` prompt section appended to the system string per turn, produces `SlashCommand[]`, returns a cached body for the `Skill` tool, and expands `/name args`. The log persists the EXPANDED model-facing content while the manager's ring keeps the original user text, so live and resumed model history agree.

**Tech Stack:** TypeScript ESM (`.js` suffixes), Node 20, existing `server/skills.ts` + `shared/skills.ts`, vitest, no new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-09-native-session-persistence-design.md` (add a P1.4 section in Task 4).

## Global Constraints

- No behavior change for `server/providers/claude/**` EXCEPT the two explicitly noted shared changes: `Skill` is added to `READONLY_TOOL_NAMES` in `server/permission-broker.ts` (a skill load is read-only), and `SessionSkillManager.reloadSkills` also broadcasts an EMPTY `commands-changed` (so a fully deleted catalog clears the picker). Both are called out as intentional shared improvements with tests.
- `supportedCommands`/`reloadSkills().skills` return valid `SlashCommand[]` (`name`, `description`, `argumentHint` required, optional `aliases`/`builtin`).
- `Options.skills: undefined` maps to the CLI's **name-only** default (names listed without descriptions, model-invocable) — NOT to "all with descriptions". `'all'` = name + description; `string[]` = allowlist; `[]` = none. Override `'on'` must not resurrect a skill outside a spawn allowlist.
- Frontmatter additions in `server/skills.ts`/`shared/skills.ts` are additive optional fields only (`disableModelInvocation`, `userInvocable`, `argumentHint`).
- The `Skill` tool never forks (forked execution deferred). `/skill` expansion preserves every non-text content block (images/files) and only rewrites the leading text block.
- The log persists the EXPANDED content; the manager's ring keeps the original `/name args` text (UI), so live and resumed model history agree.
- `supportsPlugins` stays `false`; `applyFlagSettings` accepts ONLY `skillOverrides` and throws on any other key (plugin toggles fail loudly).
- Tests must isolate `claudeConfigDir()` (set `CLAUDE_CONFIG_DIR` to a temp dir) so real user skills never leak into assertions.
- No new dependencies; diagnostics through `createLogger`; focused tests first, full gate before the final commit.

## Review Focus

1. **Policy matrix** — `undefined`/`'all'`/allowlist/`[]` and each override state map to the right availability in `section()`, `commands()`, `bodyOf()` and `expand()`; base-allowlist + `'on'` cannot resurrect an excluded skill.
2. **Prompt freshness** — `reloadSkills` and `applyFlagSettings` recompute the section; a turn in flight keeps its own string; the nested Agent system is a live getter.
3. **User-turn integrity** — the ring keeps `/name args`; the log and model history carry the expanded body; images/files survive expansion.
4. **Catalog shape + empty broadcast** — valid `SlashCommand[]`, and a fully deleted catalog still emits `commands-changed` (now also for claude).
5. **Body correctness** — the `Skill` tool returns the actual body with `Arguments: …` appended; unknown/disabled/`disable-model-invocation` names error without any stream call; `user-invocable: false` blocks `/name` but not the model.
6. **Depth/preset isolation** — nested Agent calls see the current skills (live getter), and `Skill` stays in nested tools.

Each line gets a test in the owning task.

**Interfaces:**
- `parseSkillFrontmatter` additionally returns `disableModelInvocation?: boolean`, `userInvocable?: boolean`, `argumentHint?: string`; `SkillRecord` carries them as optional fields.
- Produces:
  ```ts
  export class NativeSkillCatalog {
    constructor(cwd: string | undefined)
    configure(skills: string[] | 'all' | undefined): void       // spawn Options.skills
    applyOverrides(overrides: Record<string, 'on' | 'name-only' | 'user-invocable-only' | 'off'>): void  // REPLACES the override map
    reload(): Promise<void>                                       // discover + cache bodies
    section(): string                                             // '' when nothing is listable
    commands(): Array<{ name: string; description: string; argumentHint: string; builtin?: boolean }>
    bodyOf(name: string): { text: string; isError?: boolean }     // from the cache
    expand(name: string): { body: string } | null                 // for a user `/name` turn
  }
  ```
  State resolution per skill: `state = overrides[name] ?? baseState(name)`.
  - base: `undefined` → `name-only` for every valid skill; `'all'` → `on` for every valid skill; `string[]` → `on` for listed, `off` otherwise; `[]` → `off` for all.
  - `section()`: for every skill whose state is `on` or `name-only`, sorted by name — `on` renders `- name: description`, `name-only` renders `- name`. Wrapped as `<available_skills>\n…\n</available_skills>`; `''` when empty.
  - `commands()`: every skill with `state !== 'off'` AND `userInvocable !== false`, as `{name, description, argumentHint: record.argumentHint ?? ''}`.
  - `bodyOf(name)`: allowed when `state ∈ {on, name-only}` AND `disableModelInvocation !== true`; returns the cached body, else `{text: 'unknown skill: <name>', isError: true}`.
  - `expand(name)`: allowed when `state !== 'off'` AND `userInvocable !== false`; returns `{body}` from the cache, else `null` (even for `name-only`/`user-invocable-only`).
  - `reload()` re-runs `listSkills(cwd)` and caches bodies for the selected set; the initial call is lazy (awaited before the first turn).

## Execution decisions

- **`Options.skills: undefined` = the CLI's name-only default** (names listed without descriptions, model-invocable). This is the actual documented SDK/app default (`shared/skills.ts`'s policy projection), not "all with descriptions". `'all'` = name + description, `string[]` = allowlist, `[]` = none.
- **`name-only` ≠ `user-invocable-only`.** The former lists the name without description but stays model-invocable; the latter is hidden from the model and only `/name` works. `off` hides everywhere. Override `'on'` cannot resurrect a skill outside a spawn allowlist. And `disable-model-invocation: true` CLAMPS the effective state to `user-invocable-only` (or `off`) — such a skill never appears in `section()`, and no override can lift it (verified against the installed CLI binary). Duplicate names dedupe project-wins; invalid records are dropped before the dedupe (a broken project skill falls back to a valid same-named user skill).
- **`NativeSkillCatalog` caches bodies at reload.** `reload()` is async (re-reads both skill roots through `listSkills`) and caches the whole SKILL.md text, frontmatter included, ≤1 MiB each; every later `section()` / `commands()` / `bodyOf()` / `expand()` is a synchronous cache read. A file that grows past the cap after discovery is skipped rather than failing the whole pass. The spawn policy and the override layer are stored separately from discovery, so configure-before/after-reload makes no difference.
- **The prompt section is rebuilt per turn; the subagent prompt reads it through a live getter.** A running turn keeps the string it started with, while a nested Agent call sees the current catalog. `Skill` rides every tool list (nested ones too), returns the cached body, and appends `\n\nArguments: <args>` when `args` is present; unknown / `off` / `disable-model-invocation` names error without any stream call. Forked skill execution is not implemented.
- **`/skill` expansion rewrites only the leading text block.** String content is matched as a whole; for block content only the FIRST text block is rewritten and every image/file block is preserved. A miss (non-command, unknown skill, `off`) passes through untouched.
- **The log persists the expanded content; the ring keeps the original `/name args`.** The log is the model's history, so it must contain what the model actually saw — otherwise live and resumed histories would diverge. The UI transcript still shows what the user typed while the session is live, but that guarantee is **LIVE-only**: on RESUME the client replays the log, so the transcript renders the expanded SKILL.md (with its frontmatter) rather than the typed `/demo args`. Accepted cosmetic consequence of persisting the expanded content for model-history consistency.
- **Consumed ⇒ persisted on every path.** A failed skill-discovery pass still writes the consumed user turn to the log (the ORIGINAL text — there is no expanded body to write) before the turn fails loudly, because the client has already marked the turn "sent". The happy path persists the expanded body.
- **A discovery failure intentionally trades strict live/resume parity for durability.** The persisted user event records a turn the live model never saw (the stream was never called), and the `turn/end { error }` close is persisted too. On RESUME that user turn is part of the model history, so the resumed model can answer the prompt the live turn dropped. Intentional: a "sent" prompt must never vanish from the durable log.
- **`applyFlagSettings` accepts ONLY `skillOverrides`** (plugin toggles fail loudly); it REPLACES the override map each call (`{}` restores the spawn default).
- **`supportedCommands` awaits the CURRENT discovery, and `reloadSkills` re-assigns `skillsReady`.** A `/commands` fetch right after spawn cannot race discovery into an empty answer; a manual reload both supersedes the construction snapshot and recovers the session from a failed pass for every per-turn await from then on.
- **`Skill` is added to `READONLY_TOOL_NAMES` AND `SAFE_AUTO_TOOLS`** (a skill load only reads SKILL.md into the conversation — no mutation, no network) and **`commands-changed` broadcasts empty lists too** — intentional shared behavior improvements covering both providers.
- **Deferred:** plugin-sourced skills (`Options.plugins`), forked skill execution, `getContextUsage` `includedSkills`/`skillFrontmatter` breakdown, `opts.agent` main-session presets (native currently ignores `opts.agent`; it is NOT already covered by the subagent store).
